# Team 23 Feedback

## Strengths
The repository is very detailed and organized. The project structure is easy to follow, and the README clearly explains where important documents and source files are located. It is also nice that the team included architecture documents, ADRs, user stories, and testing information because it shows strong planning and teamwork. The deployed website link also makes the project easy to access and try. The actual gameplay is easy to pick up and user's can jump straight into playing with no confusion. Displaying the outcome of the code being typed on the right is very engaging and helps users understand what the code they are typing actually does, rather than just mindlessly typing code. It is also great how errors are highlighted in red so the user knows exactly where they went wrong. Finally, displaying the game stat's at the end is also a nice touch, and encourages users to keep playing to get bettery accuracy or WPM. Overall great product so far!

## Improvements
The README contains a lot of useful information, but some sections could be shortened or simplified for new visitors. Adding a few screenshots or GIFs of gameplay near the top could also help people quickly understand what the game looks like before reading the full documentation. Currently, users cannot continue unless they correct their error, which slows the game down and makes it a little frustrating. It might be worth exploring what gameplay would look like if users could continue typing. I think this is also affecting the Accuracy and Errors displayed at the end as the user is forced to correct everything. It would also be better if the buttons on the homepage stayed highlighted after being clicked because it is a little unclear what has been selected and if the user should select Start. Finally, it seems to get stuck on the Round Complete page. 

## Question
How do you plan to keep the gameplay challenging and fun for players who already type quickly? Or is this purely to see your typing stats like a site like MonkeyType? Will there be 6 levels per difficulty selection? Will some of the levels incorporate JavaScript, or will they all be HTML/CSS?

## Suggestion
It could be interesting to add an overall theme or a points system to make the experience feel more like a game and keep users engaged. It might also be cool to include a leaderboard system where users can create accounts and compete for high scores, similar to how MonkeyType does it.
